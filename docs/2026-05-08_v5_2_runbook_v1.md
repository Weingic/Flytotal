# v5.2 现场 Runbook

## 1. 编译检查

```powershell
$env:Path += ";$env:USERPROFILE\.platformio\penv\Scripts"
pio run
pio run -d examples\nodeb_c3_identity_uart
```

通过标准：

- 两个工程都编译成功。
- 没有新增 `.pio/`、`outputs/`、`captures/` 运行产物进入 Git。

## 2. NodeA 单板测试

```powershell
pio run -t upload --upload-port COM_NODEA
pio device monitor --port COM_NODEA --baud 115200
```

串口命令：

```text
CONFIG,STATUS
FUSION,STATUS
FUSION,DEBUG
FUSION,ENABLE,1
FUSION,STATUS
FUSION,ENABLE,0
FUSION,STATUS
```

通过标准：

- 默认 `fusion_enabled=0`。
- 开启后 `fusion_enabled=1`。
- 关闭后回到旧三源计数逻辑。
- 无 LD2451 时 `ld2451_valid=0`，主循环不阻塞。

## 3. NodeA + NodeB 联调

烧录 NodeB：

```powershell
pio run -d examples\nodeb_c3_identity_uart -t upload --upload-port COM_NODEB
```

接线：

```text
NodeB GPIO4 TX -> NodeA GPIO15 RX
NodeB GPIO5 RX <- NodeA GPIO16 TX
NodeB GND     -> NodeA GND
```

通过标准：

- NodeA 输出 `nodeb_online=1`。
- 拔掉或重启 NodeB 后，约 `3s` 变为 `nodeb_online=0`。
- NodeA 不阻塞，串口命令仍可响应。
- 重新接回 NodeB 后，NodeA 可以重新收到 NodeB 状态。

## 4. LD2451 测试

先文本仿真：

```text
FUSION,ENABLE,1
LD2451,range_m=50,speed_mps=1.2,approach=1,valid=1
FUSION,STATUS
FUSION,DEBUG
LD2451,CLEAR
```

通过标准：

- `ld2451_valid=1`
- `ld2451_range_m=50.00`
- `far_motion_trigger=1`
- `fusion_stage=FAR`
- 单 LD2451 远距触发最多为 `LOW`

实测距离：

```text
10m / 30m / 50m / 80m / 100m
```

每个距离保存串口记录、Dashboard 截图和 10-20 秒现场视频。

## 7. 回退步骤

如果现场 v5.2 出现无法接受的问题：

```powershell

git log --oneline --decorate -5
git checkout 963ee66
pio run
pio run -t upload --upload-port COM_NODEA
```

如果只想回到当前分支最新提交：

```powershell
git checkout feat/win-codex
git pull
pio run
```

回退后必须重新验证：

- `CONFIG,STATUS`
- `FUSION,STATUS`
- LD2450 轨迹是否正常
- 云台是否扫描/跟踪正常

## 给小白的解释

现场不要一上来就跑 100m。先确认板子能编译、串口能回话、NodeB 掉线能报警，再接雷达和摄像头。这样出了问题能定位，不会所有问题混在一起。
