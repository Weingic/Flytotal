# Flytotal 物联网竞赛答辩 Q&A V2

更新：2026-07-13。回答只使用当前代码、量化文件和明确的待测边界。

## Q1：这是物联网项目，还是一个上位机视觉项目？

答：核心是 ESP32-S3 驱动的 AIoT 云边闭环。NodeA 采集雷达和身份数据、融合主机视觉状态、运行风险/事件状态机、上传非音视频结构化摘要，并校验和执行豆包下发指令。PC 负责 V4b 推理、Dashboard 和证据归档，是现场网关，不取代 ESP32-S3 核心控制器。

## Q2：对应乐鑫命题的四条硬要求是什么？

答：ESP32-S3 是核心主控；LD2450、LD2451、RID 和视觉状态构成多源融合；系统接入火山方舟豆包；设备既上传非音视频传感摘要，也能处理 `ADJUST_THRESHOLD`、`SWITCH_MODE`、`GENERATE_ALERT` 等下行指令。最终演示用同一事件导出证明四条在一条链上成立。

## Q3：为什么视觉不直接跑在 ESP32-S3 上？

答：当前 V4b ONNX 在 PC 网关运行，这是实际实现边界。ESP32-S3 负责实时传感、融合、事件和云端控制。这样能先证明完整 AIoT 闭环，但不能说已经把 YOLO 部署到 MCU；若后续迁移模型，那是新的工程阶段。

## Q4：系统能在 100 米稳定识别无人机吗？

答：不能这样承诺。100 米目前只属于 LD2451 远距运动预警的设计和待测范围；LD2451 不是无人机专用雷达。无人机类别确认依赖 V4b、近距轨迹和 RID，10/30/50 米结果必须按外场原视频如实填写。

## Q5：LD2451 不是无人机雷达，为什么还使用？

答：它只做“远处有运动目标”的早期触发，输出距离、速度和接近趋势。系统不会把 LD2451 单源结果直接包装成无人机识别，而是等待近距二维轨迹、视觉或身份链提供更强证据。

## Q6：怎么做多传感器融合？

答：ESP32-S3 汇合 LD2450 的二维位置/速度、LD2451 的远距运动、NodeB 的 RID 身份，以及主机转发的视觉锁定和置信度。融合输出 `fusion_stage/fusion_level/fusion_confidence/fusion_reason`，风险状态机再决定是否形成事件。台架逻辑已验证，真实距离分层仍待外场。

## Q7：云端大模型不是只做聊天吗？

答：不是。NodeA 上传事件号、雷达运动、身份、风险和融合摘要，不上传原始音视频；豆包返回受约束 JSON，包括威胁等级、说明和命令。边缘端解析后再做白名单、范围和威胁状态校验，云端不能直接绕过本地安全策略。

## Q8：云端能下发哪些动作？

答：当前模型输出协议只允许 `NONE`、`ADJUST_THRESHOLD`、`SWITCH_MODE` 和 `GENERATE_ALERT`；后三类分别调整阈值、切换融合模式或生成本地告警。`TRIGGER_PARACHUTE` 不在模型允许列表中，NodeA 仅保留防御性解析分支：即使收到该旧命令也会返回 `PARACHUTE_REJECTED_NOT_INTEGRATED`、`applied=false` 和 `edge_veto=1`，不会执行未集成硬件。

## Q9：断网后系统会失效吗？

答：不会卡死。雷达、RID、视觉状态、融合、风险和事件都在本地继续；云请求失败会记录 `CLOUD_FAILED_LOCAL_FALLBACK`。断网时不能获得新的大模型研判和下行，这是能力降级，不应显示成云端在线。

## Q10：怎么防止云端错误指令？

答：CloudClient 只接受固定 JSON 命令类型，NodeA 还会做参数范围、当前威胁状态和安全降级检查，并记录 `cloud_command_applied/effect/reason/source_event_id`。严格证据要求来源事件号与当前事件一致，防止跨事件复用旧指令。

## Q11：怎么防止把人、车、鸟当成无人机？

答：视觉侧 V4b 使用困难负样本训练和两次连续检测确认后才自动起锁；雷达侧还有轨迹持续性和多旋翼特征。当前离线独立集 Precision 为 `0.95506`、Recall 为 `0.77982`，COCO 压力中仍有飞机 `15/97`、车辆 `18/535`、鸟 `4/125` 图片触发，所以不能声称已经消除误报，外场负样本矩阵仍必须完成。

## Q12：大雾、弱光或黑帧怎么办？

答：当前证据守门拒绝平均亮度低于 5、高于 250，或亮度标准差低于 2 的画面，避免黑帧和无内容帧进入抓拍。雾天和弱光的真实召回没有测完，因此只说明“无效画面会被拒绝、系统可依靠其他传感器降级”，不背诵没有来源的天气置信度数字。

## Q13：为什么轨迹确认是 3 次？

答：当前 `TrackConfig::ConfirmFrames=3`，作用是过滤单次瞬时目标；V4b 自动起锁另要求两次稳定检测。3 次是当前工程参数，不声称它已经在所有场景最优。真实误报、漏报和延迟数据出来后，才能判断是否需要调整。

## Q14：V4b 为什么使用 0.45 阈值？

答：它是在独立测试和困难负样本曲线上选定并部署的固定运行值。增大阈值通常降低误触发但增加漏检，减小阈值提高召回但增加误触发。正式外场不临时改阈值，保证结果可比较。

## Q15：NodeB 的 RID 是真实无人机 Remote ID 吗？

答：当前 NodeB 可以提供模拟身份链和白名单逻辑证明，但没有完成对任意真实无人机 Remote ID 的普适接收验证。答辩时应说“模拟 RID 身份链/合作目标逻辑”，不能说已经识别所有真实无人机 RID。

## Q16：NodeB 或某个雷达掉线会怎样？

答：状态会明确变为离线或无效，主循环继续运行，并减少对应证据源。系统不会用旧值假装在线，但融合可信度和可用范围会下降。具体降级效果要展示状态字段和测试记录，不说“其他距离完全不受影响”。

## Q17：多节点 handoff 已经是真实无线接力了吗？

答：不是。当前 handoff 状态和字段是单 NodeA 按目标距离推导的接力预留；NodeB 当前主要负责身份链。真正的多节点无线目标交接尚未完成，属于后续扩展，不能列为当前实测创新。

## Q18：目前最硬的三条证据是什么？

答：第一，V4b 独立评测与 ONNX 运行链，P95 为 `34.816 ms`；第二，历史 Ark 事件证明云端 API 与 `GENERATE_ALERT -> ALERT_GENERATED`；第三，ESP32-S3 固件构建、固件安全守门 `108/108` 与 PC 工具回归 `22/22 PASS`。它们仍是分开的证据，最终还缺同一新事件严格 `15/15` 和真实外场矩阵。

## Q19：现在能保证国一吗？

答：不能用工程语言保证奖项。当前项目满足乐鑫赛题方向并具备较完整代码链，但国一竞争力还取决于同场云边实证、真实目标统计、稳定演示、物理完成度和答辩表达。未完成项必须在提交前补齐，不能用文档或离线回归代替。

## Q20：API key 和隐私怎么处理？

答：密钥放在本地忽略文件，不进入仓库、截图、视频或导出；云端只上传结构化传感和事件摘要，不上传原始视频。若密钥曾公开展示，应立即在服务端轮换，而不是只从代码里删除。
