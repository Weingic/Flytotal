# Flytotal v5.2 答辩素材包

Last updated: 2026-05-03

## 本轮 P0 目标

把 v5.2 从“功能已经补强”收成“评委追问时有真实代码、可视化和证据路径”的版本。本轮只做 P0：

- 默认 `FusionConfig::Enabled=false`，基础验收先稳住。
- Demo 前用 `FUSION,ENABLE,1` 手动开启 v5.2 融合。
- 视觉置信度通过 `VISION,CONF,confidence=0.82,stability=0.91,state=TRACKING` 进入主链。
- Dashboard 显示 CSRT/KCF 绿框、YOLO/光流红框、NodeA/NodeB 协同视图。
- 证据工具能读历史 `captures` 或样例数据，输出 PNG/JSON。

## Demo 串口命令

```text
FUSION,STATUS
FUSION,ENABLE,1
VISION,CONF,confidence=0.82,stability=0.91,state=TRACKING
FUSION,DEBUG
FUSION,ENABLE,0
```

答辩时可以这样解释：默认关闭是为了保住基础六场景；开启后才进入 v5.2 多模态融合演示。缺 LD2451、缺 NodeB、缺视觉时，都必须降级为无效输入，不能卡住主循环。

## Q&A 预案

**1. 100 m 能不能精准识别无人机？**  
不能承诺稳定识别小型无人机。100 m 在本项目中只验收远距运动预警触发，真正确认依赖近距雷达、视觉证据和 RID 身份链。

**2. LD2451 不是专门测无人机的，为什么能用？**  
它不作为“无人机识别雷达”，只作为低成本远距运动触发源。项目把它放在 FAR 阶段，最多先给 LOW/MID 预警，不直接给最终判定。

**3. 雾天、弱光、视觉不好怎么办？**  
视觉受限时雷达和 RID 先承担存在性、连续性和身份链判断；视觉清晰时再提供目标确认和证据固化。

**4. 如何降低误报？**  
多旋翼筛选使用速度区间、持续时长、速度方差和航向变化率。没有真实标签时只输出特征图和 `needs_labels`，不伪造 ROC。

**5. ESP32 的价值是什么？**  
ESP32-S3 / C3 不承担云端大模型计算，主要承担边缘采集、串口协议、节点状态、无线通信和协同感知字段上报。

## 给小白的解释

这是什么：这是一张答辩素材清单，把你要展示的图、命令和话术都放在一起。
有什么用：老师或评委问到“创新点有没有证据”时，你不用临场乱找，可以直接打开对应图和网页。
你现在该怎么做：先跑证据命令，再打开 Dashboard 录红绿双框和协同视图，最后把实测截图路径补到这份文档里。
