# Flytotal v5.2 总纲

## 项目定位

v5.2 的目标不是把低成本样机包装成军用级系统，而是把“能跑的样机”升级成“能解释、能测试、能录证据”的低空监测验证平台。

核心边界：

- `100m` 只验收远距运动预警触发，不承诺稳定识别小型无人机。
- `LD2451` 不是无人机专用雷达，本项目只把它作为远距运动触发源。
- 视觉用于确认目标和固化证据，不作为唯一判定源。
- `ESP32-S3` 负责边缘采集、串口融合、状态输出和节点协同，复杂视觉算法仍在 PC/云端侧运行。

## 导师建议到系统目标

1. 雷达距离不足：补 `LD2451` 远距触发，覆盖 `10m/30m/50m/80m/100m` 测试记录。
2. 创新点不够凝练：固定为三点，多模态融合、抗干扰筛选、ESP32 多节点协同。
3. 数据大屏展示度不足：Dashboard 展示融合阶段、视觉红绿双框、NodeA/NodeB 状态。
4. 复杂环境解释不足：弱光/雾天视觉降级时由雷达主导，视觉清晰时辅助确认。

## v5.2 系统架构

```text
LD2450 近距雷达 ----\
LD2451 远距触发 -----> NodeA ESP32-S3 ----> 串口状态 / Dashboard / 证据工具
NodeB C3 身份链 ----/
视觉桥接 PC --------/
```

主链分工：

- `src/main.cpp`：任务调度、串口命令、状态输出、运行时数据同步。
- `lib/Fusion/`：FAR/MID/NEAR 融合阶段、置信度、投票和一致性判断。
- `lib/Ld2451Parser/`：LD2451 官方二进制帧解析和文本仿真入口。
- `lib/TrackManager/`：航迹确认、多旋翼特征评分。
- `lib/GimbalPredictor/`：带限幅和低通滤波的二阶云台预测。
- `tools/`：视觉桥接、Dashboard、融合/云台/协同仿真和答辩证据。

## 三个答辩创新点

1. 复杂环境下的多模态融合感知：LD2450 + LD2451 + RID/NodeB + 视觉置信度，按 FAR/MID/NEAR 分阶段处理。
2. 抗干扰与非无人机过滤：多旋翼特征筛选使用速度区间、持续时长、悬停稳定性、航向变化率。
3. ESP32 边缘节点和协同感知：NodeA/NodeB 串口联调、在线状态、掉线检测、协同视图和后续 handoff 扩展。

## 当前必须验收

- `pio run` 和 NodeB 工程编译通过。
- 默认 `FusionConfig::Enabled=false`，基础实测不被高级融合回归影响。
- `FUSION,ENABLE,1` 后可以进入 v5.2 融合调试。
- NodeB 掉线约 `3s` 后 `nodeb_online=0`，NodeA 不阻塞。
- 无 LD2451 数据时 `ld2451_valid=0`，主循环不阻塞。
- Dashboard 能显示视觉置信度、红绿双框、NodeA/NodeB 状态。

## 给小白的解释

你可以把 v5.2 理解成“先听远处有没有动静，再用近处雷达、身份链和摄像头确认”。远处 LD2451 只负责提醒，不能单独说它就是无人机；真正展示时要用多源信息一起说明。
